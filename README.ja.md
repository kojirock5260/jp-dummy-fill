# jp-dummy-fill

[English](README.md)

日本語のフォームに、通るダミーデータを 1 クリックで入れる Chrome 拡張。

日本のフォームは英語圏のダミー入力ツールでは通らない。フリガナは全角カタカナ、
郵便番号は 3+4 に分割、電話は 3 分割、都道府県は select、郵便番号を入れると住所が
補完される。jp-dummy-fill は、それを全部知っている。

## 思想

- **警告を出さない**。権限は `activeTab` `scripting` `contextMenus` の 3 つ。「すべてのウェブサイトのデータを読み取り・変更」は出ない
- **何も送らない、何も残さない**。外部通信ゼロ。`storage` も使わない
- **足さない**。設定画面なし、アカウントなし、課金なし
- **通る**。日本のフォームのバリデーションと補完を前提に値を作る
- **架空**。個人に当たらない値を使う。実在するのは郵便番号と町域まで

## プライバシー

収集も送信もしない。押したタブのフォーム欄の属性を読み、空いている欄に値を書き、
入れた数を返すだけ。`storage` 権限を取っていないので、何も保存されない。
詳細は [プライバシーポリシー](PRIVACY.md)（英語）を参照。

## 開発

```bash
npm install
npm run build   # dist/ に出力
```

ビルドしたものを手元の Chrome で動かす場合:

1. `chrome://extensions` を開く
2. 右上「デベロッパーモード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」→ `dist/` フォルダを選択

`tests/fixtures/jp-form-test.html` を開いて試せる。`file:` で開くなら
「ファイルの URL へのアクセスを許可する」を ON にする。`http://localhost` で配っても
よい。

## 使い方

入口は 3 つ。どれも activeTab が付く。

| 入口 | 動作 |
|---|---|
| ツールバーのアイコン | このページに入力 |
| 右クリックメニュー | 下記 3 項目 |
| ショートカット | `Cmd+Shift+Y`：入力、`Cmd+Shift+U`：住所を遠隔地・離島に替える…、`Cmd+Shift+K`：フォーカスのある欄にデータを埋める…（Windows / Linux は `Ctrl`）。F を避けたのは Fake Filler の既定と重なるため |

右クリックメニュー:

| 項目 | 動き |
|---|---|
| このページに入力 | ページを開いたときの人で、空いている欄を埋める。人はページを開くたびに変わる（使い捨て） |
| 住所を遠隔地・離島に替える… | 場所を選ぶパレットを開く。選ぶと人はそのまま、**住所の欄だけ上書き**（下記） |
| この欄にデータを埋める… | 右クリックした欄のそばにパレットを開く（下記） |

人物は開くたびに別の人になるので、会員登録を何度試してもメールアドレスが前回と被らない。
「固定データで入力」「別人で入力」は無い。別の人が欲しければページを開き直す。

人物には番号が付いていて、メールアドレスの末尾（`shou.abe.4213@example.jp` の 4213）で
分かる。登録済みの値と同じ人を出し直したいときは、「この欄にデータを埋める…」のパレットに
その番号を打って Enter。番号はページ内に持ち、タブが違えば別の人。

**送料や配送可否のテスト**には「住所を遠隔地・離島に替える…」（`Cmd+Shift+U`）。パレットに
配送業者が区分している場所が並ぶので、「さど」「おきなわ」のように打って Enter。人はそのままで、
郵便番号・都道府県・住所・FAX の欄だけがその場所に書き換わる。埋まったページでも効く。
「元の住所に戻す」で戻る。

| 区分 | 並ぶ場所 |
|---|---|
| 配送料の区分が別の地域 | 北海道（札幌市）、九州（福岡市）、沖縄本島（那覇市） |
| 離島 | 礼文島、奥尻島、飛島、伊豆大島、八丈島、父島、佐渡島、隠岐、小豆島、対馬、福江島、屋久島、奄美大島、与論島、宮古島、石垣島、与那国島、南大東島 |

区分はヤマト運輸（北海道・沖縄が別地帯、離島の追加料金なし）、佐川急便（離島中継料の
対象一覧）、Amazon.co.jp（「本州・四国」と「北海道・九州・沖縄・離島」）に合わせた。
飛島は市の一部だけが離島で、市区町村名では判定できない例として入れてある。

**空のまま残った欄や、違う値が入った欄**は、その欄を右クリックして「この欄にデータを埋める…」を
選ぶか、欄にフォーカスして `Cmd+Shift+K`。欄のそばに小さなパレットが開くので、
「しく」（市区町村）「せい」（フリガナ セイ）のように打って Enter。値はページの他の欄と
同じ人物から、その欄の書式で作り、**上書き**で入る。値がある欄を書き換えるのはここだけ。
人が欄を名指しで選んでいるからです。パレットには規則が何と判定していたかも出て、
手で選んだ欄は DevTools のコンソール（Verbose）に残るので、規則を育てる材料になります。

**都道府県が既に選ばれているフォーム**では、その県の住所で埋める。先に select だけ
手で選べば、狙った県になる。

**値がある欄は常に飛ばす**。上書きモードは無い。書き換えるのは、人が名指しした欄と、
選んだ場所に替える住所の欄だけ。checkbox は同意（規約・プライバシー）だけ ON にし、
それ以外は触らない。

完了時はアイコンのバッジに入れた欄数を 2 秒だけ出す。入れられなかったときは `!` と
理由をツールチップに出す。

## 何が入るか

| 欄 | 例 |
|---|---|
| 氏名（分割・単一） | 阿部 / 翔、阿部　翔 |
| カナ | アベ / ショウ。label や placeholder がひらがなならひらがな、pattern が半角カナなら半角カナ |
| 郵便番号 | 100-0013。7 桁の欄なら 1000013、分割なら 100 / 0013 |
| 都道府県 | 東京都。select は名前・「東京」・JIS コード・カナのどれでも当てる |
| 住所 | 千代田区霞が関4-10-12 霞が関ビル 301。都道府県・市区町村・番地・建物・部屋番号のどの欄があるかで中身を変える。Amazon の 市区町村 / 丁目・番地・号 / 建物名 / 部屋番号 なら 千代田区霞が関 / 4-10-12 / 霞が関ビル / 301 |
| 住所フリガナ | トウキョウトチヨダクカスミガセキ4-10-12 |
| 電話 | 090-0947-6865。3 つの欄なら 3-4-4 に分割。FAX は固定電話の書式 |
| メール・パスワード | shou.abe.4213@example.jp（番号が付くので登録が衝突しない）、固定の `Dummy!Pass01`。確認欄には同じ値 |
| 生年月日 | `type=date` なら 1984-07-18、元号の select があれば 昭和 / 59 / 7 / 18 |
| 年齢・性別 | 42、男性（radio / select） |
| 会社 | 阿部商事株式会社、アベショウジ、営業部、課長 |
| 自由記述 | 日本語 2〜3 文。lorem ipsum は使わない |

電話番号は制度上存在しない。携帯は未指定帯の `090-0XXX-XXXX`、固定は 1 で始まる
市内局番（割り当てられない）。`example.jp` は JPRS の例示用予約ドメイン。
郵便番号・都道府県・市区町村・町域は日本郵便のデータにある実在の組で、番地と建物は架空。

## 郵便番号→住所補完との共存

日本のフォームの多くは郵便番号から住所を補完する（yubinbango, ajaxzip3）。拡張は
郵便番号を先に書いて 300ms 待ち、その時点で空の欄だけを書く。どちらが勝っても
データは同じ実在の組なので、結果は同じになる。補完ライブラリは町域までしか入れない
ことが多いので、値が人物の町域で終わっていて数字を含まない住所欄には、番地（建物の
欄が無ければ建物も）を末尾に足す。「値がある欄は触らない」の唯一の例外。

キーイベントは投げない。autokana 系のふりがな自動入力を誤作動させないため。

## 構成

```
src/
  domain/        純粋なルール。DOM も chrome.* も触らない。ユニットテスト済み
    classify.ts  欄種の判定（docs/field-rules.md §1〜§2）
    group.ts     分割欄（§3）
    person.ts    seed から一人ぶん（§4）
    render.ts    欄種ごとの値。文字種と書式（§5）
    plan.ts      上の流れを 1 つに繋いだもの
  application/   ブラウザ API 越しの副作用（入力の起動、通知、i18n）
  presentation/  DOM から集める（collect）、DOM へ書く（write）
  background.ts  Service Worker。入口が 3 つあるだけ
  content.ts     注入されるスクリプト。seed を持ち、二重注入を防ぐ
data/
  addresses.src.json   手で管理する 65 件（zip / kind / zone / areaCode / note、離島は name）
  addresses.json       生成物。上に都道府県・市区町村・町域と読みを足したもの
  names.json           姓 100・名 男女各 50。読み付き
docs/
  spec.md              仕様書
  field-rules.md       欄の判定ルール
```

`domain` は上の層を import しない。何を書くかを決める部分は全部素の Node でテスト
でき、DOM を触る層は jsdom で `tests/fixtures/` のフォームごとテストしている。

## データ

```bash
npm run data          # addresses.src.json から日本郵便のデータで addresses.json を作り直す
npm run data:check    # 元リストや今の郵便番号データと合っていなければ失敗する
```

`yubin`（日本郵便の郵便番号データを同梱した npm）は devDependency。拡張には入れない。
拡張が持つのは生成物の 65 件だけ。

## 実サイトでの確認

判定ルールは実サイト 8 件（楽天会員登録、EC-CUBE 4 デモ、自治体の LoGoフォーム、
Google フォーム、Marketo、Snow Monkey Forms、Contact Form 7、Amazon の住所追加）の
フォームで確かめた。
欄の作りは `tests/fixtures/forms/` に、期待する欄種は `tests/domain/forms.test.ts` に
あり、ルールを変えてどれかが壊れればテストが落ちる。何が分かって何を直したかと、
`scripts/capture-form.js` で新しいフォームを足す手順は `docs/forms-survey.md` にある。

## Notes

- **英語圏のフォームは対象外**。名前は日本語のみ。そこは Fake Filler の領分
- **別ドメインの iframe の中のフォームには届かない**（Salesforce のお問い合わせがそう）。
  readonly の input で作られたドロップダウン（Vuetify、MUI）と `div[role=radio]`
  （Google フォーム）にも入れられない
- **サイト内検索の欄と、選択肢の value が URL の select は触らない**。後者は選ぶと
  ページが移動する
- **自分の本当の住所は保存しない**。それは Chrome の自動入力の領分
- **押すまで何もしない**。ページ常駐も、フォーム検出の自動起動もない
- **使えないページがある**。ウェブストア、`chrome://`、および「ファイルの URL への
  アクセスを許可」が OFF のときの `file://`。ツールバーアイコンに赤い `!` と理由の tooltip を出す
- **京都の通り名表記、法人番号、クレジットカードのテスト番号、Firefox 対応**は
  このバージョンには無い
